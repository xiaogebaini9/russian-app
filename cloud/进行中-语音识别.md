## 线上现状

云端 https://aimisi.top。前端与 API 由**同一个 Worker** 提供
（`cloud/wrangler.toml` 里 `[assets] directory = "../www"`），所以一次 `wrangler deploy`
会同时更新网页端和接口；APK 用户要等下次出包。

| 环节 | 实现 |
|---|---|
| 实时识别 | `POST /api/voice` → Workers AI `@cf/openai/whisper-large-v3-turbo`；固定 `language=ru`、`vad_filter`、`condition_on_previous_text:false`、`hallucination_silence_threshold` |
| 精修识别 | `POST /api/voice-hq` → **同一个 turbo 模型**，`beam_size=10` + `initial_prompt`（课程术语表＋前文） |
| 翻译 | `POST /api/class-translate` → DeepSeek，带课程术语表，不预设输入一定是俄语 |
| 本地路径 | `proxy.js` 的 `/api/voice`、`/api/voice-hq` → 本机 `whisper/stt_server.py`（faster-whisper `large-v3-turbo-ct2`） |

### ⚠️ 「精修 = 换个更大的模型」这个设定不成立

Cloudflare 模型目录里名称含 whisper 的只有 `whisper`、`whisper-large-v3-turbo`、`whisper-tiny-en`，
**`@cf/openai/whisper-large-v3` 不存在**（2026-09-10 核实，文档端点 404）。本地磁盘也只有 turbo 一份。
所以精修与实时的差别现在是**解码参数（beam_size）＋ 是否带上下文**，不是模型级别。
要再往上提准确率，方向是「喂对输入」（大块送 + initial_prompt），不是「换大模型」。

## 2026-09-10 一批修复（已提交本地，**未 push / 未 deploy**）

1. **静音幻听**：识别接口此前只传 `audio` 一个参数，没指定 `language`（每段独立猜语种）、没开 VAD，
   Whisper 于是在静音/底噪片断上"脑补"出训练语料里的字幕套话——`you`、`Thank you.`、
   `Thanks for watching!`、`Продолжение следует`。已补参数；前端 `classSendText` 加了
   `asrLooksValid` 收口闸门，4 条识别路径（实时 / HQ 补识 / 回放精修 / 回放兜底）全覆盖。
2. **`confidence` 字段**：后端此前从不返回它 → 前端「⚠️ 识别不准」标记**在云端从未亮过**
   （只有本机走 proxy 时才亮）。现从 `segments[].avg_logprob` 取最小值返回，标记真正生效。
   `language` 也修正了取值层级（原来读顶层，恒为空串；实际在 `transcription_info` 里）。
3. **回放重翻**：由"按静音切碎片"改为约 30 秒整块送达（Whisper 按 ~30 秒窗口训练）；
   每条请求带 `initial_prompt` = 课程术语表 + 前文；修掉原设计里识别期间漏录的音频；
   字幕时间戳按录音内位置换算（此前全被写成"重翻那一刻"，整批堆在时间轴末尾）。
4. **屏幕常亮**：课堂/回放期间申请 Wake Lock，切回前台自动补申请 —— 此前全项目零命中，
   屏幕一锁就是整节课白录。
5. **字幕板增量渲染**：新句子只追加节点，不再每次全量重建 200 条（原先历史句子跟着一起重播动画）。

## 待办

- [ ] **Groq whisper 备源**：Workers AI 免费额度每天 1 万 neurons，吃紧时用 Groq（需用户注册拿 key）
- [ ] **超长课堂内存风险**：`classSessionChunks` 全程堆在内存，3 小时以上要改成边录边写 IndexedDB
- [ ] **APK 内导出录音**：`a[download]` 在 Capacitor WebView 里可能不生效，需 `@capacitor/filesystem`
      （录音本身已存 IndexedDB，不会丢）
- [ ] **课堂识别并发无节流**：`classRecognize` 每段 fire-and-forget，网络差时会多路并发上传，
      没有队列/背压/上限
- [ ] **静音阈值硬编码**：`rms<0.015` + 1200ms 写死在两处，教室底噪一高就永不触发，
      没有环境噪声校准入口
- [ ] **课堂历史「清空」语义含糊**：只清字幕板，IndexedDB 会话记录仍在，再进"历史"又能看到
- [ ] **回放重翻的额度提示**：目前只提示"仍会消耗深度额度"，没给预计句数

## 踩坑备忘（保留）

- `/api/voice` 的输入必须是 **base64 字符串**（`{audio: b64}`）；传数组或 ArrayBuffer 会报 schema 错。
- 单段上限 8MB；录音格式优先 `audio/mp4;codecs=mp4a.40.2`，回退 webm/opus（Whisper 对 mp4/aac 更稳）。
- `wrangler.toml` 需要 `[ai] binding = "AI"`。
- 语音请求必须携带登录会话 header，否则服务端的课堂体验额度拦截不生效（已修，`fa5f2da`）。
- 改完前端记得走 `sync.bat` 同步三份拷贝（root / `www/` / `android/app/src/main/assets/public/`）并递增
  `sw.js` 的 `CACHE` 版本号。
