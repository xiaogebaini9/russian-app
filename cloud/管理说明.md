# 云端服务管理说明

> 2026-09-02 部署完成。深度翻译已从"作者电脑"迁移到 Cloudflare 全球节点，
> 用户只需联网 + 接入码即可使用，作者电脑不再需要开机。
> **服务地址：https://aimisi.top**（国内、哈萨克斯坦均可直接访问）

## 架构

```
用户 App/APK → https://aimisi.top（Cloudflare Worker）→ DeepSeek API
                  ↑ 持有真 Key、校验接入码、扣次数、缓存
```

- 服务端代码：`cloud/worker.js`（与本地 `proxy.js` 接口完全一致）
- 接入码存储：Cloudflare KV（9 个旧码已于部署日迁移，用量记录一并保留）
- 静态页面：Worker 直接托管 `www/` 目录，手机浏览器打开 https://aimisi.top 即可当 PWA 用
- 域名：aimisi.top（阿里云注册），DNS 托管在 Cloudflare，绑定到 Worker

## 日常操作（都在本目录命令行）

前置：`cloud.json` 存了服务地址和管理令牌（已加 .gitignore，绝不能外传/上传）。

```bash
node gen-codes.js 8               # 生成 8 个码（每码每日 100 次，永久有效）
node gen-codes.js 8 --days 30     # 月卡：30 天后自动过期
node gen-codes.js 8 --total 3000  # 次数卡：总共可用 3000 次
node gen-codes.js 8 --name 客户A  # 加备注名
node gen-codes.js list            # 查看所有码、今日用量、有效期
node gen-codes.js del 4826159     # 停用某个码（立即生效）
node gen-codes.js key sk-xxx      # 更新服务端 DeepSeek Key（余额不足换key时用）
node gen-codes.js import          # 把本地 codes.json 一键同步到云端（恢复码库）
node gen-codes.js backup          # 云端码库备份到本地（生成/停用码时会自动备份）
node gen-codes.js feedback        # 查看用户反馈
node gen-codes.js feedback-done <id>  # 标记某条反馈已处理
node gen-codes.js devices         # 查看设备登记清单（IP、注册/登录账号、封禁状态）
node gen-codes.js device-block <设备号> [on|off]  # 封禁/解封设备（立即生效）
```

收费建议：月卡卖 `--days 30`（可再配 `--daily 200` 提高每日限额），次数卡卖 `--total N`。

## 免费试用

- 未填接入码的新设备自动获得 **3 天 × 每天 25 次** 深度功能试用（可调）
- 调参数：直接改 KV config 的 trial 字段，或让作者执行：
  `node gen-codes.js` 暂不覆盖此功能，试用参数通过管理接口 `/admin/trial` 修改（{days, dailyLimit}）
- 防刷四道闸（2026-09-05 起）：
  1. **设备登记**：所有带设备号的深度请求/注册/登录都会在 D1 `devices` 表永久留档
     （IP、注册和登录过的邮箱）。`node gen-codes.js devices` 查看，发现刷量直接
     `node gen-codes.js device-block <设备号>` 封禁
  2. **每设备最多注册 2 个账号**（worker.js 常量 `MAX_ACC_PER_DEVICE`），
     防同一设备注册多邮箱叠加每日额度
  3. **同一 IP 每天最多注册 5 个账号**（常量 `MAX_REG_PER_IP_DAY`，按 Cloudflare 真实
     IP 计，无法伪造），防脚本批量刷号
  4. 同一 IP 3 天内最多 5 个新试用设备（原有机制保留）；客户端设备号已做三重备份
     （localStorage + 一年期 Cookie + IndexedDB），清缓存/清站点数据不再等于换新设备
- 封禁影响范围：只限制免费试用和新注册，已购接入码用户和已绑套餐账号完全不受影响

## 用户反馈

- 用户在 App 设置 → 意见反馈 提交，内容存云端 KV
- 想让反馈即时推到你的微信：注册 pushplus.plus（免费，绑定微信），拿到 token 后
  通过管理接口 `/admin/pushplus` 填入（传空串关闭）
- 查看/处理：`node gen-codes.js feedback` / `feedback-done <id>`

## 用户账号与课堂体验

- 用户在 App 设置顶部注册/登录邮箱（密码只存哈希），收藏自动云同步
- 登录用户：词典/翻译/变位/句子解析/AI出题按账号额度使用（注册继承设备试用 3天×25/天）
- **课堂体验**：登录账号赠送 **75 句 ≈ 15 分钟**（终身一次，不占每日额度），用完后课堂需购套餐；
  体验量在 worker.js 的 `CLASSROOM_TRIAL_SENTENCES` 常量（75），改后 `wrangler deploy` 生效
- 给用户开套餐：`node gen-codes.js plan 用户邮箱 30 100`（30 天 × 每天 100 次）
- 查看用户：`node gen-codes.js users`；防刷三闸门：设备封禁 / 每设备 2 账号 / 每 IP 每日 5 注册
  （查询封禁：`/admin/devices`、`/admin/device-block`）

## 修改服务端代码后重新部署

```bash
cd cloud
wrangler deploy
```

改 `index.html` 后：跑一次 `sync.bat`（同步 www/ 和 APK 资产），再 `cd cloud && wrangler deploy`
让云端托管的网页也更新，最后 push GitHub 出新 APK。

⚠️ **重要：不要随便运行 `wrangler dev` 调试！** 新版 wrangler 的本地调试会
**直连真实的云端 KV**（不是本地模拟），调试时的导入/改码会直接改掉线上数据。

⚠️ **码库数据一律通过 gen-codes.js 管理**（它走 Worker 的管理接口）。
实测发现：用 `wrangler kv key put` 命令行直接写入的数据，线上 Worker 可能读不到
（Cloudflare KV 一致性问题），但 Worker 自己写入的数据永远读得到。
所以恢复码库用：`node gen-codes.js import`（本地 codes.json 是完整备份）。

## 本地模式（语音识别专用）

Whisper 语音识别只能跑在作者电脑上：
1. 电脑上 `node proxy.js`（旧本地代理，不用动）
2. App 设置 → 服务器地址 填 `http://作者电脑IP:8765`
3. 清空该设置则回到云端模式

注意：本地 `proxy.js` 只认本地 `codes.json` 里的码。自己用本地模式时，
在设置里直接填你的 sk- Key（直通，不占接入码额度）。
